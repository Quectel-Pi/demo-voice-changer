# 最短启动与演示指南

> 英文版见 [DEMO_GUIDE.md](DEMO_GUIDE.md)。

适用于已有可用Qt、NumPy、sounddevice/PortAudio和Rubber Band 3.3环境的源码Demo。
不是全新板卡安装验收或第三方分发许可结论；依赖边界见[README](../README.md)。
本地启动/配置回归已验证；本版本已在Pi M2独立部署并经真实窗口启动与有限恢复验证（见板端启动证据）。
2026-11-04 已启用桌面图标扩展（`ding@rastersoft.com` ACTIVE）并写入 trusted 入口，`Desktop` 上的图标可双击；
但本轮未做人工双击复验，且截图/自动点击在本板不可用。全新安装、`.deb` 与正式性能仍未验收。

## 1. 生成桌面入口

在Demo目录执行，明确选择已验证的Python；输出父目录必须存在，重名不覆盖：

```bash
.venv/bin/python -B scripts/create_desktop_launcher.py \
  --python "$PWD/.venv/bin/python" \
  --output /absolute/path/to/your-desktop/voice-changer-demo.desktop
```

将示例输出路径改为**你实际的桌面目录**，不要假定目录叫Desktop；也可选择用户应用菜单目录。
生成器只写指定文件，不安装依赖、不查询设备、不启动程序或修改系统。
源码树/解释器移动后重新生成；解释器路径不能含`%`，会明确拒绝，避免GLib误解析。
空格、引号、`$`及源码路径中的`%`已用实际GLib参数探针验证。

桌面支持图标时双击生成的入口（本板GNOME 48无图标扩展，需用应用菜单或`gio launch <文件>`）；
桌面可能要求“允许启动/信任”，由用户确认，不自动修改信任标记。已在Pi M2验证`gio launch`真实启动、640×440窗口与正常退出。
入口保留启动终端供错误提示；启动脚本只等待原生应用退出，音频仍在单个应用进程。
失败包括缺Qt、插件异常退出等，终端显示退出状态并等待回车；不是默认后台服务。
无需当前工作目录或手动设置PYTHONPATH。已有Rubber Band环境变量会传给应用。
不生成图标资源，使用系统麦克风图标；没有图标主题时不影响启动。

## 2. 每次演示

1. 戴有线耳机，确认当前系统音量安全；启动后原声、增益0dB、所有音频活动停止。
2. 点击“刷新设备”，确认输入/输出。无历史配置则填写48000/512/1及自行确认的峰值上限；当前演示路径使用0.05。
3. 点击监听并确认输出，说话并切换9预设；必要时调音高/共振峰/趣味强度，手动效果变自定义，重置保留增益。
4. 点击录音，持续说话并换几个效果；可停监听继续录音，或停录音继续监听。
5. 停录后分别试听原声/效果。回放会先释放采集，不重新套用效果/增益，结束不恢复监听。
6. 保存到新的组目录，再正常退出；双轨/参数与对齐说明见开发工作区中的录音说明。

仅录音不需要输出；仅回放不需要输入。说完后继续约1秒静音可留录音区间内的尾音。
发生设备/处理/磁盘错误时先停止并查看错误，不提高系统音量、不强杀已有RVC。

## 3. 有限恢复

- 配置为`$XDG_CONFIG_HOME/voice-changer/preferences.json`，未设置时使用`~/.config`。
  只记实际成功使用的设备名称/后端名、四个音频值和成功保存的父目录；不记录设备索引。
- 有效历史四字段仅预填，**不自动应用**；没有有效历史仍空。
  设备只在用户刷新后匹配恢复；消失、歧义或通道不足提示重选，不回退默认设备。
- 不恢复效果/增益/活动，不自动探测、采集、回放或重开已保存组；每次输出仍需确认。
- 读写与目录检查在控制线程，运行期间只更新内存，设备释放后原子写配置。
  无历史时只读且不创建配置目录；配置损坏/目录失效明确提示，原文件不自动删除。
- 写配置失败保留音频文件和待写快照，纠正路径后停止/退出可重试；退出失败保留“重试退出”窗口。

测试与未验证边界见验收索引及板端启动记录（真实设备为`pipewire`/48000/512/mono/0.05）。

## 4. 虚拟麦克风（v1）

把变声结果送给其他应用（会议/录音/直播工具）：

1. 输出设备选择 `vcmic`（显示为 `vcmic [#4, ALSA]`），输入仍选真实麦克风（如 `pipewire`）。
2. 点击“开启监听”；应用自动校验配置并创建 PipeWire 节点，无额外安全输出确认弹窗：
   `voice-changer-sink`（收）与 `voice-changer-mic`（供其他应用取用）。
3. 在其他应用里把麦克风选为 **Voice Changer Virtual Mic**。
4. 停止监听或退出应用后节点消失；不需要时不要保留后台 `pw-loopback`。

要点：

- 需要运行中的 PipeWire 用户会话和 `pw-loopback`/`pw-dump`；缺失时界面会写明原因，虚拟麦克风条目不会出现。
- **不会静默成功**：目标节点不在时 ALSA 兼容层会“假装打开成功并丢弃全部样本”，
  本实现用 `pw-dump` 校验节点，未就绪即报错。
- 输出同时只能有一个消费者语义：选 `vcmic` 时声音进入虚拟麦克风，不再自动播放到扬声器/耳机；
  想同时自己听到，请使用其他应用的监听功能或改选真实输出设备。
- 蓝牙延迟高，不建议作为虚拟麦克风路径。

## 5. 一键部署（可选）

```bash
.venv/bin/python -B scripts/deploy_demo.py \
  --destination ~/voice-changer-$(date +%Y%m%d) \
  --python /usr/bin/python3 \
  --install-audio \
  --desktop-entry ~/.local/share/applications/voice-changer.desktop
```

脚本只做四件事：复制源码（排除缓存/录音/虚拟环境）、建 `--system-site-packages` venv、
按哈希安装音频依赖、写桌面入口。**不启动音频、不改 PipeWire/音量、不碰系统服务、不安装系统包。**
`--dry-run` 只打印步骤；`--no-venv` 仅复制源码；`--archive x.tar.gz` 另存分发包。

耗时约 1–2 分钟（依赖已缓存时更快）。部署后：

```bash
~/voice-changer-YYYYMMDD/venv/bin/python -B -m voice_changer --version
```
